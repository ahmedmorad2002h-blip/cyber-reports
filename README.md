# cyber-reports

منصة الرصد والتحقيقات السيبرانية (Flask + Supabase)، تعمل على Render.

## متغيرات البيئة (Render > Environment)

لا تضع أي أسرار داخل الكود أبداً. هذه المتغيرات تُضبط في Render فقط:

| المتغير | مطلوب؟ | الوصف |
|---|---|---|
| `SUPABASE_URL` | نعم | رابط مشروع Supabase |
| `SUPABASE_KEY` | نعم | مفتاح Supabase (ويُفضّل تفعيل RLS على الجداول) |
| `SECRET_KEY` | نعم | نص عشوائي طويل لتوقيع الجلسات. بدونه يُولَّد مفتاح مؤقت ويخرج الجميع عند كل إعادة تشغيل |
| `ADMIN_PASSWORD` | اختياري | إن ضُبط يصبح هو كلمة سر حساب `admin` عند كل تشغيل (8 أحرف على الأقل). أنشئه لتدوير كلمة السر ثم احذفه لتديرها من الموقع |

| `CRON_KEY` | اختياري (موصى به) | مفتاح سري لرابط `/cron/send-pending?key=...` الذي تناديه خدمة مراقبة خارجية كل 5 دقائق (يبقي الموقع مستيقظاً ويشغّل دورة الإرسال) |
| `WHATSAPP_TOKEN` | للإرسال | رمز الوصول الدائم من Meta (System User) |
| `WHATSAPP_PHONE_NUMBER_ID` | للإرسال | معرّف رقم المُرسِل في Meta (ليس الرقم نفسه) |
| `WHATSAPP_TO` | للإرسال | رقم المستلم بصيغة دولية، مثال `9647736347557` |
| `WHATSAPP_TEMPLATE_NAME` | عملياً مطلوب | اسم قالب معتمد من Meta، جسمه متغير واحد `{{1}}` |
| `WHATSAPP_TEMPLATE_LANG` | اختياري | لغة القالب، الافتراضي `ar` |
| `WHATSAPP_HOURS` | اختياري | ساعات الإرسال بتوقيت بغداد، الافتراضي `7-16` |
| `WHATSAPP_ENABLED` | اختياري | ضع `0` لإيقاف الإرسال مؤقتاً |

لتوليد `SECRET_KEY`:

```
python -c "import secrets; print(secrets.token_hex(32))"
```

## التشغيل محلياً

```
pip install -r requirements.txt
export SUPABASE_URL=... SUPABASE_KEY=... SECRET_KEY=...
python app.py
```

## ملاحظات أمنية

- كلمات المرور 8 أحرف على الأقل.
- حماية CSRF مفعّلة على كل الطلبات من نوع POST.
- 5 محاولات دخول فاشلة تقفل المحاولة 5 دقائق.
- ملفات البلاغات الحقيقية (`cases/` وملفات `*.json`) ممنوعة بـ `.gitignore`.

## قواعد العمل

- **تعديل البلاغ:** يستطيع صاحب البلاغ (أو الأدمن) تعديله ما دام قيد المراجعة فقط. بعد الموافقة أو الرفض يُقفل نهائياً، ويُفرض ذلك في الخادم وليس في الواجهة فقط.
- **منع تكرار الرابط:** يُطبَّع الرابط قبل المقارنة (إزالة `www` ومعاملات التتبع مثل `utm_*` و`fbclid`، وتوحيد `twitter.com`/`x.com` و`t.me`/`telegram.me`، وتجاهل الشرطة الأخيرة وحالة الأحرف في النطاق)، ويُفحص أيضاً أثناء الكتابة في الاستمارة.
- **نشاط الأفراد:** لكل فرد جدول شهري (الحالات، الموافق عليها، المرفوضة، قيد المراجعة) ومعدل الرصد اليومي = عدد حالات الشهر ÷ عدد أيام الشهر الكامل. ملاحظة: حذف البلاغات الموافق عليها (تصفية الشهر) يحذفها من هذه الإحصائيات أيضاً.

## المشرف (Supervisor)

يشغّل الأدمن هذا الأمر مرة واحدة في Supabase > SQL Editor:

```sql
alter table users add column if not exists is_supervisor boolean default false;
```

بعدها يظهر مفتاح "مشرف" بجانب كل مستخدم في نافذة إدارة المستخدمين. المشرف يرى كل البلاغات والإحصائيات ويضيف مستخدمين عاديين، لكنه **لا** يوافق ولا يرفض ولا يحذف ولا يعدّل البلاغات، ولا يعدّل حسابات الأدمن/المشرفين ولا يحذف مستخدمين ولا يعيّن مشرفين. سحب الصلاحية يسري خلال دقيقة.

## الإرسال التلقائي على واتساب

- بعد الموافقة تصبح الحالة "تمت الموافقة" ثم تُرسل تلقائياً وتتحول إلى **"تمت الموافقة وتم إرسالها"**.
- الإرسال فقط من 07:00 إلى 16:00 بتوقيت بغداد؛ ما يُوافق عليه خارج الوقت ينتظر ويُرسل صباح اليوم التالي.
- الإرسال عبر **WhatsApp Business Cloud API الرسمي من Meta**: يجب تسجيل رقم المُرسِل (+9647763729009) في Meta Business، وإنشاء قالب رسالة (Utility) بمتغير واحد في الجسم واعتماده، ثم ضبط المتغيرات أعلاه. الرسائل الحرة بلا قالب لا تُقبل إلا خلال 24 ساعة من آخر رسالة من المستلم.
- لا يُرسل البلاغ مرتين (حجز ذري)، وتُعاد المحاولة عند الأخطاء المؤقتة (حتى 6 مرات بفواصل متزايدة). أخطاء الإعداد تظهر للأدمن مع زر "إعادة المحاولة".
- على Render المجاني ينام الموقع بعد 15 دقيقة؛ اجعل UptimeRobot (أو cron-job.org) يفتح كل 5 دقائق: `https://<موقعك>/cron/send-pending?key=<CRON_KEY>`.
- عند تفعيل واتساب، حذف الموافق عليها الجماعي لا يحذف البلاغات التي لم تُرسل بعد.

## الرتبة وسبب الرفض

- الرتبة يختارها المستخدم مرة واحدة عند أول بلاغ وتُحفظ على حسابه، ولا تُسأل بعدها.
- رفض البلاغ يتطلب كتابة سبب (3 أحرف على الأقل) ويُفرض في الخادم؛ يظهر السبب لصاحب البلاغ وللأدمن.
- كل الأوقات المسجلة بتوقيت بغداد (UTC+3).
